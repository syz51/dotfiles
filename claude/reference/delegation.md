# Delegating tracks

These rules are part of the global instructions (`~/.claude/CLAUDE.md`, Delegation section) and have the same force. Read them before you start a subagent or a delegate.

- Split work by context, not by type of work: each agent owns its whole track, from investigation through implementation and tests, and one area's work never passes from one agent to another, such as an explorer's findings to a worker. Choose each track's agent by what the whole track does: read-only investigation to `explorer`, file edits, other state-changing work and hard debugging or reasoning, with any fix, to `worker`. Keep the count low, and don't override an agent's configured model or effort.
- Settle only the interfaces tracks share, then give each agent a standalone brief with these parts in order: the goal; what it needs from this conversation; those interfaces; scope and limits; acceptance checks. A brief never asks for open work only as a report part: open items go on the board, filed by you where the child never files, before the report to me names their ids. A child, in a subagent or its own thread, loads these instructions, the project's instructions and the board rules itself, so the brief names only what differs from them. The `explorer` and `worker` definitions give their report's shape, and the `reviewer` its own; for any other child, the brief ends with the report it expects.
- Give each track that edits files its own worktree through the runtime's worktree facility when one is available, never one made in the shell. A new worktree never has uncommitted changes, so transfer required inputs explicitly and have the child verify them in its checkout. Afterwards bring its changes into this checkout and remove the worktree and its branch, unless I say otherwise. Other tracks share this checkout; never let two tracks, or a track and you, change the same files or state at the same time.
- Keep planning across tracks, judgment, communication, and completion verification yourself. Check each delegated result against its brief and diff, and run the acceptance checks and any missing ones, then fix what remains yourself. Delegate a correction only when it is again a parallel track: continue the agent that did the track when it and its checkout still exist, otherwise start a new task with the original brief and findings.
