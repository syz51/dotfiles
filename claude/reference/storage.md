# Storage

These rules are part of the global instructions (`~/.claude/CLAUDE.md`, Storage section) and have the same force. Read them before you use `storagectl` or split work across machines.

- Keep work that another machine or a later session may read on the shared storage through `storagectl`, not only in a local folder: downloads, datasets, run outputs and handoff files. Start with `storagectl dests` to see which destinations are online, then use `put`, `get`, `ls`, `find`, `fetch <url> <dest>:<path>/` or `run --to <dest>:<path> -- <command>`. The commands, and how a service requests its own allocation, are in `docs/storage/README.md` in syz51/vps.
- Choose the destination by need: `cloud` (Tencent COS; always reachable, deleted files recoverable for 30 days) or `sai` (12 GiB) when the data must not depend on a Mac being awake; `pro` for large data, offline while the Pro sleeps; `air` for small files; `svps` for small results only, since its uploads are slow. On sai and svps, `storagectl` works only in root login shells.
- Split work across machines when another one suits a step better: `sai` for large downloads and COS-heavy steps, the Pro for large data and long CPU jobs. From the Air or the Pro, run such a step with `storagectl run --on sai|pro --to <dest>:<path> [--stage <file or dir>] -- <command>`. It runs detached as that machine's `storage-runner` account and prints a job id; the command writes results to `$STORAGE_OUT`, which is sent to `--to` with the job's log, also when it fails. Follow it with `storagectl status|logs|cancel <id>` or `storagectl jobs --on <machine>`. Stage only small inputs (up to 1 GiB); pass larger ones through destinations, which the job reads with `storagectl` and the runner's own keys. sai jobs get one CPU and 768 MiB and cannot reach local or tailnet services other than the storage pools. Never run workloads as root on sai or svps; svps runs no jobs. Threads on the Pro through a linked T3 environment (`vps-45`) are being built.
- Report what got in the way as Feedback with `about` `storage`, giving the machine, command, error and workaround, then continue with the workaround. A task that needed a T3 thread on another machine also goes as a note on `vps-45` while it is open.
