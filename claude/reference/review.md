# Running the review

These rules are part of the global instructions (`~/.claude/CLAUDE.md`, Review section) and have the same force. Read them before you start the `reviewer` agent.

- Run the review in the background, so this thread stays free to answer me: commit the final diff, then start the `reviewer` agent with the Agent tool and `run_in_background: true`, with only the commit's range as its prompt, such as `origin/main...<SHA>`. It works in this checkout on the session's model at its own effort, so give it no worktree, model or effort, and don't run it through another agent or a skill call. It returns its findings as JSON, each with a category. While it runs, answer my messages and continue work that leaves that diff alone, but don't push or report done until its findings are handled. Cancel and restart it only when the diff changes while it still runs. After it returns, fixes get the affected checks, never another review.
- Check each finding against the code before deciding. Fix every one that is a real defect in what the change is meant to do and verify the fix, delegating only fixes that split into parallel tracks under the Delegation section, then rerun the affected checks. Report the findings you reject as not real, with the reason; file the real ones outside what the change is meant to do as found work under the Work board section, or report them where there is no board, instead of fixing them.
- Once you have decided on every finding, record the outcomes: call `ReportFindings` once with every finding, its category and its outcome, `fixed` for one you fixed, `no_change_needed` for one that is wrong or intentional, and `skipped` for a real one you filed or did not apply. Split more than 32 findings into calls of 32, and record a review without findings as an empty list. The categories are `correctness`, `security`, `reliability`, `efficiency`, `simplification`, `test-coverage`, `conventions` and `docs`. Report the result in your reply as well.
