# Merging pull requests

These rules are part of the global instructions (`~/.claude/CLAUDE.md`, Autonomy section) and have the same force. That section gives the authorization to merge; read these before a `gh pr merge`.

- The guard-pr-merge hook refuses a `gh pr merge` with `--admin`, on a draft, or before every check on the head commit has passed, except `--auto` where GitHub waits for the base branch's required checks. An Actions job that GitHub never started for billing counts as passed when a non-Actions check named `<context>: <job name>` passed. Before a direct merge, it also waits for a check from each workflow at the head commit that runs on every pull request (a `pull_request` or `pull_request_target` trigger without filters), and from CircleCI where `.circleci/config.yml` exists; it passes a head commit without checks where no such CI is configured.
- Pin each merge that the guard checks to the head commit whose checks passed: `gh pr merge <number> --match-head-commit <SHA>`. The guard refuses a merge without the pin, and its refusal names the SHA and the command to rerun. GitHub then refuses the merge if a new commit was pushed after the check. A `--auto` merge where the base branch requires checks needs no pin.
- When a pull request is BEHIND a base branch that requires checks, run `gh pr update-branch`, then, as a separate command, `gh pr merge --auto` with a merge-method flag, and watch the pull request instead of waiting for each run by hand; update the branch again whenever it falls behind. Auto-merge can lag a minute or two after the checks pass; if the pull request then still sits at CLEAN, merge it directly.
- After a Bash call runs `gh pr create`, the auto-merge hook turns on auto-merge for each pull request it printed, with a merge commit, else squash, else rebase, as the repository allows. It acts only on a syz51 repository that allows auto-merge, for an open pull request that is not a draft, where the base branch requires status checks or approving reviews. It never merges at once: it skips a pull request that can merge now, which you then merge yourself once every check passes. It reports each pull request in its output and never blocks the call; where it reports a failure, turn auto-merge on yourself. You still run `gh pr update-branch` when the pull request falls BEHIND.
